## 四、ele 实测数据备忘（2026-11-04 读源码）

- 尺寸：主窗基准宽 **470**（v3.1.2 基准，≠1C 的 360）、快捷/已完成 310、簇高 640；`MIN_SCALE=0.7`、上限=屏高×0.5。
- 白条：窗 160×6，视觉条 3px（热区一半）垂直居中，日夜 α 见上。
- 吸附：`clampAnchorForEdges` = 水平保证 ±90px 可见、垂直贴顶/底部留 50px——**无磁吸**。
- 拖动跨屏：每窗独立 BrowserWindow，DPI 由系统/Chromium 处理；主进程按坐标所在屏取 scaleFactor（命中测试用）。
- 内容尺寸对比：⚠️ **原按 2K@125% 推算（作废）**。2026-11-04 实测应用所在屏为 **2K(2560×1440) @100%**，故 **1 DIP = 1 物理像素**，上面所有尺寸值在真机上的物理像素数就等于其 DIP 数值 × 簇缩放。
- **审计结论（2026-11-04）**：全部尺寸改动均为 DIP 值、与 DPI 无关（代码 `MonitorLayout` 用 `GetDpiForWindow÷96` 自动按所在屏换算，零写死），**无需因 DPI 更正而改任何数值**。
- 唯一受错误推断影响的是**表述**：我曾称"滚动条 4 DIP 视觉条在 125% 下无法绝对居中"——在 100% 屏上 4 DIP = 4 物理像素（偶数）、命中区 8 DIP = 8 像素 → **每侧恰好 2 像素，精确居中**。该改动本身正确。

## 六、滚动条位置问题（2026-11-04 第三轮，用户提问「14 是谁的内边距」）

**用户观察**：滚动条比改动前更远离窗口右边缘；且「滚动条的位置不需要变」。

**实测结论（截图像素采样，簇缩放 1.167、DPI 100%）**：
- `Padding="14,0,9,0"` 是**列表滚动容器 `ListScroll` 的内边距**，不是待办窗口的；窗口内容根 `CardContent`（360×640）无任何内边距。
- **WPF 的 `ScrollViewer.Padding` 会把滚动条一起往里推**（实测：滚动条右缘内缩量 = 右内边距值）。
  这是本仓库此前的错误认知（以为 Padding 只作用于内容、滚动条贴边）。
- 因此把右内边距 6 → 9（批次 4a，为让内容两侧等距）时，滚动条被同步推外 3 DIP → 用户看到的「更远」。

**修法**：改用**覆盖式 ScrollViewer 模板**（`PART_VerticalScrollBar` 与内容同格、右对齐）：
- 滚动条不再参与内边距、也不再占内容宽度 → 内容两侧可独立设为 14/14 等距；
- 顺带回答上一轮用户提问「滚动条能不能不占位」——现在不占位；
- 实测：内容两侧内边距 **14.6 / 14.6 DIP**（等距 ✓）；滑块宽 **4.3 DIP**（用户定的 4px 规格 ✓）；
  滑块高 = 窗高 **45.4%**（按比例 → ScrollableHeight/ViewportHeight 已正确传到滚动条，联动可用 ✓）；
  滚动条右缘距窗口矩形右边 6.9 DIP = 窗口自身不可见缩放宽边（`WindowStyle=None`+`CanResize`），即贴客户区右缘。

**开发自定**：滚动条位置取「贴客户区右缘」（最稳定、不再随内边距漂移）。若用户希望距右缘留特定间隙，再按其数值加 inset。

## 七、滚动条命中区宽度根因（2026-11-04 第四轮）

**用户指出**：他报的是 8px（因为列表右边距窗口右边 14px，所以给滚动条命中区 8px），但实际看起来不是 8；
并明确「我不懂 DIP/DPI，我按 px 说」。→ **汇报口径改为 px，不再用 DIP 术语。**

**排查过程（截图像素 + 染色探针）**：
1. 给 ScrollBar 背景染色 → 命中区实际覆盖 20px（≈16 DIP），不是代码里的 8。
2. 把模板里 ScrollBar 的 `Width` 改 30 → 命中区变 36px（≈29 DIP）→ **说明 Width 属性确实生效**。
3. 由此锁定：**WPF 主题默认 ScrollBar 样式带 `MinWidth`（= 系统滚动条宽度，96DPI 下 17）**，
   而 **`MinWidth` 优先于 `Width`** → 写 8 被抬到 17；写 30 因为 30>17 所以生效。
   （排查中还发现我模板里 `Visibility` 属性重复写了两遍，导致"隐藏 ScrollBar"的探针失效，一度误判为"另一个 ScrollBar"。）

**修法**：ScrollBar 样式与模板元素上显式 `MinWidth="0"`。

**实测结果**：命中区 **8.02 DIP（= 8，正确）**；滑块 4 DIP 居中 → 右缘距窗口右边 **1.6 DIP（≈2）**。
与用户预期（14px 空间 → 命中区 8px → 滑块居中 → 每侧 2px）一致。

**教训**：改 WPF 控件尺寸时，除 `Width/Height` 还要清 `MinWidth/MinHeight`——主题样式会带系统最小值，
且 MinWidth 优先于 Width；这类"写 8 得 16"的问题编译与单测都不报。

## 八、跨屏（两块屏缩放不同）问题与决策（2026-11-04 第五轮，开发自定）

**用户实测三连**：① 两屏来回拖，窗口一路变小；② 从左往右拖、模板窗碰到两屏边界时两窗分离很远，松手后保持；③ 跨屏后内容显示错乱（截图可见时钟被裁、模板窗内容溢出）。

**根因**：
1. **窗口变小** = 我加的 D7 跨屏重钳把"按屏钳制后的值"写回了用户档位字段，而该字段又被存进 `ClusterScale` → 档位被逐次污染。
   修法：拆成 `_storedScale`（用户档位/存档）+ `EffectiveScale(area,anchor)`（按屏钳制的生效值），布局只用生效值。
2. **两窗分离 + 内容错乱** = **DIP 是"按屏"的**。两块屏缩放不同（2K@100% / 4K@175%），
   整簇一半在这屏、一半在那屏时，模板窗的位置按主窗所在屏的 DIP 空间算出、却落在另一块屏上 →
   位置与尺寸被按另一套缩放解释 → 分离 + 内容错乱。

**决策（开发自定，按"尽量少影响其它需求"原则）**：**整簇不跨屏**——拖动时把整簇钳在所在屏内；
整簇宽于该屏时退化为 ele 口径（主窗 ≥90px 可见），不加额外限制。

**考虑过的其它选项**：
- (b) 把整簇布局从 DIP 改成物理像素、并逐窗按所在屏 DPI 设内容缩放：工作量大、等于重写布局层，且混合 DPI 观感仍需反复打磨 → 不做。
- (c) 不动：用户会被"两窗分离"卡住 → 不可接受。

**兼容性**：与既有裁定不冲突——D2（主窗 ≥90px 可见）保留为"整簇放不下时"的兜底；需求 §2.1"分辨率变化/拔显示器→回可见范围"不受影响。
**恢复**：用户当前那次"两窗分离"的状态，重启应用即恢复（启动时会钳回可见范围）。

**另**：本轮同时修掉 —— 模板批量退出后选中样式残留（只追加快路径未清旧行）、
已完成行悬停样式（上轮我声称加了、实际没加，我的疏漏）、标题栏顶部 12 留白不可拖动（拖动挂在带 Margin 的 Grid 上）、
时间轴竖线未与圆点同心（两者各自被像素对齐独立吸附 → 关掉这两处的布局取整，共用几何中心）。

## 九、尺寸规则变更 + 与 ele 的冲突（2026-11-04 第六轮，用户指令）

**用户指令**：分辨率对尺寸的影响**只应出现在首次安装**（唯一目的是防止初始窗口过大超出屏幕导致无法调整卡死）；
之后一律以用户自己对窗口的调整为准。

**落地**：
- 布局档位 `LayoutScale` = **用户档位（存档 ClusterScale）本身，不按屏钳制** → 换分辨率/跨屏都不再改尺寸。
- 仅首次安装（无存档位置）由 `ResolveAnchor` 按屏高 1/3 给默认值并按屏钳制。
- 已有存档时只做绝对范围保护（0.15~3.0），不按屏钳制。
- 缩放手柄拖拽期间仍按当前屏限制（用户主动调整时的自然边界），写入的是用户档位。

**⚠️ 与 ele 的冲突（已按用户最新指令执行，特此记录）**：
ele 是**每次布局都按屏钳制**（`effectiveClusterScale` → `clampClusterScale(stored, base, wa)`；下限 0.7、上限屏高×0.5），
即"分辨率每次都影响尺寸"。用户 2026-11-04 的指令与之相反 → **以用户最新指令为准**（用户指令优先于 ele 对照）。
ele 中与本条不冲突的部分（拖动 90/50 可见钳制、仅上边缘吸附、缩进、托盘 3 秒等）照旧沿用。

**同轮修复**：模板批量「选中→直接返回」仍有选中样式残留（用户二次反馈）。
真根因：上轮我加的"批量态变化才整表重建"判断本身没错，但**调用方漏传批量态**——
`PushBatchBar` / `RefreshAllViews` 调 `SetTemplateRows(rows, max)` 时第三参默认 false，
于是进出批量都被当作"批量态没变"、照旧走只追加快路径，旧行 Selected 不清。
修法：两处调用补传批量态。**并用前后截图对比自动验证通过**（退出后画面与进批量前 0% 差异）。

## 十、跨屏钳制回退 + 全选不同步（2026-11-04 第七轮）

1. **跨屏"没法拖过去"**：第八节我加的"整簇不跨屏"钳制是按**主窗所在屏**判定的 → 主窗永远跨不过边界 → 彻底无法跨屏（用户实测"现在应用没法跨屏我验证不了"）。**已回退**：
   拖动钳制改回"按主窗所在屏"（ele clampAnchorForEdges 口径）——主窗可一直往右拖到只剩 90px 可见，
   其中心越过边界后 `MonitorFromWindow` 切到新屏，继续往新屏移动 ⇒ **跨屏可移动**。
   → 遗留：整簇跨两块**缩放不同**的屏时，模板窗会被按另一套缩放解释（第八节描述的"两窗分离"）
   **仍未解决**，需要一个真正的多 DPI 布局方案（见下）。用户 2026-11-04 已确认暂无法验证跨屏。

2. **模板批量「全选」后计数器涨了但行不显示选中**：根因=我那个"只追加"快路径——
   进批量后 `_rowsBatchActive` 已为 true、全选时行 id 与批量态都没变 → 走只追加 → **旧行的 Selected 没被同步**。
   修法：只追加分支里**就地同步已有行的 Selected**（INPC 可观察属性，不重建容器、不闪烁）。
   **前后截图对比自动验证：全选前后画面差异 98%（10 行全部出现选中底色），计数 0→10（PASS）**，
   脚本入库 `docs/tools/verify-selectall.ps1`。

**多 DPI 布局：采用 (a)（开发自定，最小改动）** —— 模板窗不越过主窗所在屏的右缘（越界时贴边裁切、
保留 40 DIP 可见），从而不会被放到另一块缩放不同的屏上。
考虑过但未采用：

## 十一、尺寸规则定稿（2026-11-04 第八轮，用户拍板"改"）

**用户裁定**：窗口钳制**有必要**；但钳制**不需要考虑缩放倍率**——因为 DIP 已被系统缩放归一化
（175% 屏上 1 DIP = 1.75 物理像素），按 DIP 工作区算 1/4~2/3 屏高就天然包含了缩放的影响。

**定稿规则**：
| 场合 | 尺寸怎么定 |
|---|---|
| 首次安装（无存档） | 按屏高 **1/3** 给默认，并按屏钳制 |
| 之后每次布局 | **生效值 = 用户档位按当前屏工作区钳制到 [1/4, 2/3] 屏高（绝对下限 192 DIP）** |
| 存档（ClusterScale） | **只存用户档位，永不写入钳制值** → 拖回大屏自动恢复用户自己的大小 |
| 缩放手柄拖拽中 | 按当前屏限制（写入用户档位） |

**为什么这样**：
- 不钳制时，用户在 4K 竖屏把窗口拉到极大、拖回 2K 屏后**窗高超过屏高、拖动角标跑到屏外抓不到**
  （2026-11-04 用户实测，窗口 823×1463 落在 2K 屏 1440 之外）→ 必须钳制。
- 当年"越拖越小"的根因不是钳制本身，而是把钳制值**写回了存档**；现在拆成 `_storedScale` + `LayoutScale(area,anchor)` 后，
  钳制只在生效值上发生，档位不被污染。
- 这正是 ele `effectiveClusterScale`（只钳生效值、stored 不动）的做法，与用户直觉一致。

**实测验证**：修复后重启，用户那个卡住的窗口从 `823×1463 @(418,-1471)` 自动变为
`540×960 @(418,0)`——960 恰为 2/3 × 1440，角标回到屏内可达。

### 新增踩坑（务必记住）

22. **WPF DatePicker 弹层的白底/圆角不能挂在外层 Border 上**：打开弹层时 DatePicker 会把 `PART_Calendar` 放进 `PART_Popup`，外层容器不参与该弹窗的渲染 → 实测底色**完全丢失**（只有文字和蓝色块画出来，看着像透明浮层）。修法：背景/描边/圆角/投影一律画进 **Calendar 自己的模板**里；Popup 内容直接放 Calendar。
23. **截屏抓不到分层窗口**：`Graphics.CopyFromScreen`（BitBlt 无 CAPTUREBLT）和 `PrintWindow(PW_RENDERFULLCONTENT)` 都抓不到 `WS_EX_LAYERED` 窗口的内容（实测 exstyle=0x8080088）。WPF `AllowsTransparency=True` 的 Popup 就是分层窗口 → 自检必须用 **BitBlt + `CAPTUREBLT`(0x40000000)**，否则会误判"底色没画"。
24. **`CalendarButton` 没有 `IsSelected`**（只有 `CalendarDayButton` 有），它用 `HasSelectedDays`；`PART_MonthView` 必须 **7 列 7 行**，且**第 0 行由控件填入星期标题**（模板里只留 6 行日期，星期标题用 `CalendarItem.DayTitleTemplateResourceKey` 的 DataTemplate 定制）。
25. **UIA `TogglePattern.Toggle()` 不触发 WPF CheckBox 的 Click**（只翻 IsChecked 本地值）→ 自动化验证批量勾选必须走**键盘空格**（与真机点击同一条 `ButtonBase.OnClick` 链）；否则会误报"勾选失效"。
26. **PowerShell 5.1 脚本含中文必须带 UTF-8 BOM**（踩坑 18 已记，本轮再次踩到：`'打开'` 变乱码 → 按名查找恒为空）；**UIA Invoke 打在模态窗按钮上会阻塞到窗口关闭**（探针会"卡住"，应改用后台作业或换入口）。
