## 一、这一批做了什么（一句话）

只造"数据底座"：你的待办数据能被正确读取、判定逾期、跨天结算、安全存回——**界面上看不到任何变化**（UI 仍是模板壳）。

## 二、你会看到什么

- 代码仓库多出"数据核心"（`src/TodoWpf.Core`）与只读验收探针（`src/TodoWpf.DataCheck`）；
- 你自己机器上的数据文件**不会被改动**：本批没有任何"保存/写入"入口，探针全程只读。

## 三、怎么操作验证（真机步骤）

**方式一（推荐，零打字）**：双击仓库根目录的 `验收-批次01.cmd`——自动依次执行下面三步，结尾由探针打印中文"怎么看结果"。脚本本身为纯 ASCII 英文外壳（避免控制台编码问题），中文输出来自 dotnet 与探针本身。

## 四、什么算通过

- `dotnet build` 0 错误 0 警告；`dotnet test` 全绿（94 用例）；
- 探针读你的真实旧档：条数/设置/窗口记忆与旧版看到的一致、不报错、**文件修改时间不变**（确实只读）；

## 七、本批定稿的两个决策（修订记录 R3/R4）

1. **数据落点**：WPF 版独立路径 `%APPDATA%\桌面待办-WPF\data.json`；首次启动若新路径无数据而旧版档案存在 → 自动复制过来（不删原件、幂等）。两版可共存，数据此后各自独立。
2. **探针保留**：`src/TodoWpf.DataCheck` 作为"旧 data.json 可读"的真机验收工具，长期保留（后续批次可继续用它核对数据口径）。

## 八、已知形态差异（不影响兼容）

- 非 BMP 字符（emoji）写出时由 .NET 编码器转义为代理对（`\uD83D\uDE00`），旧版 `JSON.stringify` 写原字符——两者 JSON 语义等价，互读无碍（单测已锁定该行为）。
- 旧档若无 `posIsTodoAnchor` 字段：读取时原样保留坐标、不套用 Electron 版的一次性坐标迁移（窗口几何模型由后续"三窗壳/窗口行为"批次定义）。
