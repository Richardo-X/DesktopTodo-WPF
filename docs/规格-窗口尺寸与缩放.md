# 规格 · 窗口尺寸与缩放（WPF 版）

> 状态：草案 v0.2（2026-11-01 收口：去掉与已确认项重复的待定条目）。
> 适用范围：新外观全部窗口（主窗 / 模板窗 / 二级窗 / 确认框 / 气泡 / 收纳条）。
> 数值分两类：**结构值**＝由内容推导、落地后不变；**待调值**＝先占位、真机后调（标 `*`）。
> 唯一实现基准是 `docs/参考/新外观原型/1C-时间轴-可交互.html`。

---

## 0. 一句话总则

所有尺寸用 **DIP**；**视觉尺寸 = 布局尺寸 × 倍数**；上限按**当前显示器的工作区**实时计算；持久化**只存数值、不存屏幕坐标**。

---

## 1. 术语

| 词 | 含义 |
|---|---|
| **DIP** | 设备无关像素（1/96 英寸）。WPF 的所有尺寸都是 DIP；原型里的 CSS px 与它同值 |
| **基准尺寸** | 设计稿原始尺寸：主窗 360×640、模板窗宽 260、二级窗 420×560 |
| **布局尺寸** | 实际参与排版的尺寸（主窗高度可调，见下） |
| **视觉尺寸** | 屏幕上看到的尺寸 = 布局尺寸 × 缩放倍数 |
| **工作区** | 当前显示器去掉任务栏后的可用区域，单位 DIP（多屏要按窗口所在那块屏取） |
| **等比缩放** | 右下角手柄，整张卡片连同文字图标一起按倍数缩放 |
| **高度调整** | 底边手柄，只拉长/压短，字大小不变 |
| **重钳** | 按当前工作区把已存的尺寸压回允许范围（不重置成默认值） |

## 2. 档位分类（四类，用户 2026-10-30 确认）

| 档位 | 窗口 | 等比缩放 | 高度调整 | 同步关系 |
|---|---|---|---|---|
| **A 主控** | 待办主窗 | 有（右下角） | 有（底边） | 作为其它窗的基准 |
| **B 从属** | 模板窗 | 无手柄 | 无手柄 | 只跟随主窗的等比缩放；不跟随高度 |
| **C 独立档** | 二级窗四组：编辑 / 详情 / 设置 / 历史 | 有 | 有 | 组内共享一组值，组间完全独立 |
| **D 固定** | 确认框、悬停气泡、收纳条、系统文件对话框 | 无 | 无 | 尺寸由内容或平台决定 |

**C 组的分组（沿用原型四组）**：`edit`＝待办新建/编辑 + 模板新建/编辑；`detail`＝详情（已完成与历史共用）；`settings`＝设置；`history`＝历史记录。

**D 类的例外**：悬停气泡没有自己的手柄（归 D 类），但**跟随主窗等比缩放（1:1）**，且**必须保留透明 + 圆角 + 投影的独立窗口**，不受“系统外壳”方案约束（2026-10-30 定）。

---

## 3. 各档规则

### A 主控（主窗）

- 水平尺寸**固定 360**（× 倍数），不提供宽度拖拽。
- 垂直尺寸＝布局高度 H（可调），视觉高 = H × 倍数。
- **H 下限 = 模板窗满额时的自身高度**（见 §4，当前 448）。目的：两个窗底边永不错位。
- **H 上限 = 工作区高 − 24（四周边距 12）÷ 倍数**，另设设计兜底 1200*。
- **倍数下限 0.7**；上限 = `min(1.5*, 工作区宽 ÷ 360, 工作区高 ÷ H)`。
  - 超屏**只计算主窗**：模板窗是否展开不影响上限（用户 2026-10-30 确认）。
- 初始：倍数 1.0，高度 = 默认高度（§4）。
- 必须始终竖长：垂直 > 水平（360×448 起，整个区间成立）。

### B 从属（模板窗）

- 宽 260 × 主窗倍数；高度 = 内容自适应。
- **只跟随主窗的等比缩放**；主窗只改高度时，模板窗一个像素都不动。
- 内容上限：条数上限（10）× 行高（36）+ 头 + 动作行 + 边距 ≈ 448；内部滚动。
- 无手柄、不单独记忆尺寸。

### C 独立档（四个二级窗组）

- 两个手柄，只影响本组；组内两个窗共用一组值。
- 倍数：0.7 ~ `min(1.4*, 工作区宽 ÷ 420, 工作区高 ÷ H)`。
- 高度：360* ~ `min(工作区高 ÷ 倍数, 900*)`。
- 初始：倍数 1.0；**详情窗高度 438**（H 定义列表：2 边框 + 40 标题 + 8 上距 + 94 三行属性 + 15 分隔线 + 265 正文 + 14 下距），其余三组 560；居中于主窗当前视觉矩形。
- 详情窗结构（`2026-10-31` 定稿，方案 H）：标题栏（返回 + 居中标题 + 右侧删除）→ 三行定义列表（创建/完成/状态）→ 1px 分隔线 → 无框正文直铺；不再使用内容框底色与圆角。

### D 固定

| 窗口 | 尺寸（DIP） | 说明 |
|---|---|---|
| 确认框 | 340 × 内容高（约 200） | 固定宽、居中 |
| 悬停气泡 | 280 宽 × 内容高 | 水平固定、垂直随内容；跟随主窗等比缩放（1:1）；透明窗 |
| 收纳条 | 160 × 6 | 贴屏幕顶边时的可见条（沿用 Electron 口径，待确认*） |
| 系统文件对话框 | 系统决定 | CSV 导入导出 |

## 4. 默认尺寸与「屏幕的一半」

**屏幕的一半 = 当前显示器工作区高度（DIP）÷ 2**（用户 2026-10-30 确认；按 DIP，不按分辨率/英寸）。

**它是出厂尺寸，不是硬上限**（用户 2026-10-30 裁定，做法二）：半屏只约束“首次打开多大”，用户仍可手动拖到工作区上限。

```
可用宽 = 工作区宽 − 24
可用高 = 工作区高 − 24
默认高度 = clamp(可用高 ÷ 2, 448, 640)
默认宽度 = 360
```

优先级：**不越界 > 内容下限 448 > 不超过半屏 > 尽量用满基准 640**。

各屏结果（示例）：

| 屏幕 / 缩放 | 工作区（DIP，约） | 默认尺寸 |
|---|---|---|
| 1366×768 @100% | 1342×704 | 360×448（半屏 352，被下限兜住） |
| 1920×1080 @100% | 1896×1016 | 360×508 |
| 2560×1440 @100% | 2536×1400 | 360×640 |
| 2560×1440 @125% | 2024×1080 | 360×540 |
| 3840×2160 @150% | 2536×1368 | 360×640 |

### 主窗最小垂直尺寸的构成（结构值）

> **主窗最小垂直尺寸 = 模板窗满额（10 条）时的自身高度**

实测拆解（原型 v2.34）：边框 2 + 标题区 41.5 + 动作行 36 + 列表 10×36=360 + 列表底留白 8 = **447.5 → 取整 448**。

- 用“满额”而不是“当前条数”：否则最小高度会随模板增删跳动。
- 该值随三个参数联动：行高、模板条数上限、标题区/动作行高度。
- WPF 侧建议加一条单测：**主窗最小高度 == 模板窗满 10 条时的高度**，防止日后改行高却忘了同步。

## 6. 同步关系

1. 主窗 ↔ 模板窗：**只同步等比缩放**；高度不同步。
2. 主窗 ↔ 二级窗：**不同步**（二级窗只以主窗矩形为居中基准）。
3. 二级窗组内：倍数与高度**共用**；组间独立。
4. 确认框、收纳条：**不参与任何同步**；气泡无自己的手柄，但整体跟随主窗缩放（1:1）。

---

## 7. 重钳时机（必须处理，否则会出屏）

| 事件 | 处理 |
|---|---|
| 启动恢复上次尺寸 | 按当前工作区重钳 |
| 改系统缩放比例（DPI 变化） | DIP 值本身不变，只压越界 |
| 改分辨率 | 工作区 DIP 变小 → 压回范围 |
| 窗口移到另一块显示器 | 按那块屏的工作区重钳 |
| 开关模板窗 | **不触发**（上限只算主窗） |
| 用户手动拖拽 | 拖动过程中实时钳制，松手落盘 |

多屏取工作区：`MonitorFromWindow` + `GetMonitorInfo`（物理像素）÷ 该屏 DPI 缩放；注意排除任务栏。

---

## 8. 持久化

- 只存：主窗倍数 s、主窗布局高 H；二级窗每组存一份 s 与 H。
- 不存：屏幕坐标、物理像素尺寸。
- 首次运行用 §4 的公式算默认值；「恢复默认」按**当前屏**重新套公式。

## 12. 自绘圆角可行吗（2026-10-30 用户提问）

目的：绕开“Win10 没有系统圆角”的差异。三条路，代价都很明确：

| 做法 | 原理 | 代价 |
|---|---|---|
| **透明窗 + 自绘圆角** | AllowsTransparency=True，WPF 自己画圆角并抠透明 | 等于推翻系统外壳：不能与 WindowChrome 共存、底边拖拽要自己写、ClearType 丢失、阴影也要自绘 |
| **窗口区域裁剪（SetWindowRgn）** | 用圆角矩形区域裁窗口 | 边缘**没有抗锯齿**（锯齿边）；尺寸每变一次都要重设区域；系统阴影通常失效或出现毛边 |
| **系统圆角（现状）** | Win11 DWM | Win10 上为直角 |

**建议**：不自绘圆角，支持范围定为 **Win11**，Win10 直角降级。若必须让 Win10 也有圆角，只能在“锯齿边”和“回到透明窗”之间二选一，两者都与已定的系统外壳方案冲突。
