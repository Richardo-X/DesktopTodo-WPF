## 三、关键技术结论（新增踩坑，务必记住）

1. **WPF `Path.Stretch="Uniform"` ≠ SVG `viewBox`**：Uniform 会把几何拉伸填满盒子，导致图标系统性偏大 60~70%、线宽偏粗。正确做法：`Viewbox(目标px)` → `Canvas 24×24` → `Path`（不设 Stretch）。墨迹 = 目标px × 包围盒/24，线宽 = S × 目标px/24。
2. **`Border.CornerRadius` 超过一半时 X/Y 独立截断成椭圆角**：`CornerRadius=99` 在高 24 的元素上变成椭圆，不是胶囊。胶囊必须显式写**半高**（如 `CornerRadius=12` + `Height=24`）。
3. **`FindResource` 返回固定画笔实例，不随主题切换更新**。需要跟随主题的用 `DynamicResource`；代码里切换状态色用 `SetResourceReference(属性, 资源键)`。**`ClearValue` 会把 XAML 里的 DynamicResource 本地值一并清掉**（图钉图标消失的根因）。
4. **`SystemParameters.WorkArea` 只返回主显示器**。多屏必须 `MonitorFromWindow` + `GetMonitorInfo`（物理像素）÷ `GetDpiForWindow`。实现在 `src/TodoWpf/Windows/MonitorLayout.cs`。
5. **尺寸锚定 DIP 工作区比例 = 物理占屏比恒定**：DIP×系统缩放=物理像素，所以"屏高 1/3"在任何分辨率/缩放下物理占屏都是 1/3。窗口尺寸不能按 DIP 固定，否则跨分辨率物理大小漂移（用户实测"4K 调好拖到 1080p 变大"）。
6. 尺寸常量：`PanelLayout.MinScale=0.4`（绝对）、`MaxScale=3.0`（实际由 2/3 屏高限制）、`AbsoluteMinHeight=192`、`DefaultHeightRatio=1/3`、`MaxHeightRatio=2/3`。最小布局高 = `max(192, 工作区高/4)`。
7. **工具链**：Git Bash 里内联 PowerShell 的 `$` 会被吃掉（用单引号包命令或写 .ps1）；同文件多处替换写 python 脚本（逐处 count 验证，全中才写）；应用运行时锁 exe，build 前先 `taskkill //F //IM TodoWpf.exe`；脚本改文件后 Edit 工具缓存过期需重新 Read。
8. **图片**：会话中粘贴的截图看不到像素；磁盘路径可用程序读（PowerShell + C# LockBits 采样）。真机观感以用户为准。
9. **DPI 口径（用户 2026-11-03 嘱咐）**：设计一律以 **100% 缩放为准**（1 DIP = 1 物理像素）。用户当前 2K 屏设了 125% 缩放（DIP 空间 2048×1152），是个人显示偏好，应用不针对它做特殊处理。**计算/查验时必须换算**：截图物理像素 ÷ 1.25 = DIP；报数默认报 DIP，报物理像素要注明。规则读的是 DIP 工作区（MonitorLayout 已除以 DPI），天然是 100% 口径。
