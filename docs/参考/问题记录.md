## A. 系统快捷键与显隐

### A1. Win+D 隐藏组件（2026-09-25 提出，2026-10-05 语义定稿关闭）
- 诉求：组件不应受 Win+D（显示桌面）影响（最初口径）。
- 根因：Win11 26200 的 Show Desktop = DWM 合成层隐藏，零事件零状态，仅豁免 toggle 时刻已在置顶层/shell 拥有的窗口；事后补救（重设置顶/hide+show/改 owner/竞态抢跑/钩子内抢设）全部无效或不确定。
- 处置：历经 TOOLWINDOW→cloak 轮询→钩子抢跑（多轮真机失败）→ **语义定稿（用户裁定）**：置顶态天然免疫；未置顶=普通窗口行为（可被隐藏，再按 Win+D 恢复）。
- 状态：✅ 已关闭（2026-10-05 语义最终版，260259a）。

## C. 渲染交互缺陷

### C1. 气泡弹窗卡死（2026-10-05 报告）
- 现象：双击待办/模板文本 → 二级窗与气泡同时出现，气泡不因鼠标移开消失。
- 根因（已定位）：二级窗打开 → 三窗 setEnabled(false)（模态锁）→ 禁用窗口不收鼠标事件 → 文本 mouseleave 丢失 → hideBubble 永不触发。
- 处置 v1：veil/失焦 → hideBubble()（3f11537）——真机复测仍未解决。
- 根因 v2（2026-10-07 fake-timers 实锤）：气泡显示有 1s 延迟定时器，禁用窗口收不到 mouseleave 后**排队中的定时器到点照弹**——v1 只隐藏了已显示的气泡，未取消排队中的定时器。
- 处置 v2：content-bubble 导出 cancelBubble()（清定时器+清悬停状态+抑制标志+隐藏），veil/失焦改调（2952b59）；**气泡延迟 1s→0.5s**（用户 2026-10-07 裁定）。
- 状态：⏳ **竞态修复完成；新问题"闪一下才显示"已定位未修复**——根因=气泡窗先以全尺寸（320×160）显示、渲染层量完内容尺寸后 resizeBubble 收缩=尺寸跳变闪现（内容与上次相同时秒出）。修复方案已定：量完尺寸、贴合同窗口大小后再 showInactive（附 100ms 兜底强制显示）——下批实施。

### C2. 文本编辑光标位置失效（2026-10-06 报告）

### E2. 缩回判定能否改用"胶囊式"真实鼠标事件（用户 2026-10-11 提议，可行性探讨）
- 提议：弹出端已是"鼠标碰到白条"真实命中（C7 定稿）；缩回端能否对称地改为"鼠标离开窗口"的事件判定；进一步设想"被遮挡时收不到事件=算离开"直接用作缩回信号。
- 分析结论（四点）：
  1. **进/出在事件可观测性上天然不对称**：命中是必然可达的事件（鼠标碰到你，系统必把事件发给你，被遮挡收不到=本就不该弹）；离开是"缺席"——事件只能报告"发生了什么"，无法报告"什么没发生"，尤其鼠标经由覆盖窗口离开时。
  2. **纯"事件消失=离开"有静止反例**：鼠标停在组件上一动不动（阅读待办）同样收不到事件 → 会把组件缩到鼠标底下（明显错误）。分清"走了/没动"必须主动问光标位置（GetCursorPos+矩形判断）——即现状主进程轮询。且现状防闪烁守卫（渲染层 `lastPointerInsideAt`，四轮加）就是"事件流=鼠标在"信号，已与轮询融合：**轮询是缺席传感器、事件是命中传感器，现系统二者各用其所长**。
  3. **历史证据**：v1.0.1 之前缩回正是 DOM mouse-leave 驱动，因伪 leave（拖动接管鼠标/缩放/显隐/二级窗蒙层冻结禁用窗）整体换成主进程轮询（f5bbbb7"DOM 伪 mouse-leave 从源头消失"），三轮 8.2-1 moving 闸与四轮指针活动守卫即当时打的补丁。
  4. **"被遮挡=算离开→缩回"语义合理但需可靠遮挡感知**：WindowFromPoint 探针在贴屏顶 0~38px 异常区返回值与遮挡无关（C6.4b 实证，组件恰贴顶）；被动信号分不清"被盖/没动"（同第 2 点）；枚举全窗口比矩形重且脆。C4~C6 三轮实验均被撤销，C7 改用真实命中绕开此问题。
- 结论：维持现状（弹出=事件、缩回=轮询）是按各自物理特性选的工具，非历史包袱。事件方案在缩回端没有可感知收益（时延被 400ms 延时掩盖），纯事件方案有"永久展开"回归风险。将来若真要做"被遮挡就缩回"语义，与拖动看门狗加固同轮评估主进程感知能力。
- 状态：✅ 探讨完结（2026-10-11 归档，未动代码；方向维持现状）。
