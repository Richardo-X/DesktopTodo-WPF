## 三、执行过程中发现并修复的缺陷（T52）

| 缺陷 | 根因 | 修复 | 回归 |
|------|------|------|------|
| 退出后主题等最后变更丢失 | before-quit 中异步 flush 被进程退出截断 | preventDefault → await 落盘 → 再 quit | E2E 验收6 ✅ |
| 主进程 "Object has been destroyed" 原生弹窗（阻塞退出）| 窗口销毁后仍经旧引用访问 | safeWin() 守卫 + closed 置空引用 | 全量 E2E 11/11，无弹窗、无挂起 ✅ |
| 主窗口 preload 未加载（API 不可用）| createWindow 未传 preload 路径 | webPreferences 补 preload | 全量功能用例 ✅ |
| 多窗口状态不同步 | 子窗口提交后未广播 | commit 后向全部窗口推送最新状态 | E2E 主流程 ✅ |
| Git Bash 下 NSIS /S 被路径转换吞掉 | MSYS 参数改写 | 改用 PowerShell Start-Process | T50 ✅ |

## 一、诊断过程（证据链）

1. **像素采样**（capturePage 位图读取）：缝隙像素 = RGB(38,42,52) **完全不透明**——渲染层画上去的（纯透明区域合成后应为 0,0,0），排除系统衬底；
2. **elementsFromPoint 枚举**：缝隙点上 `.stage` 的计算底色 = rgb(38,42,52) = **#262a34**，与 ConfirmDialog 夜间 `.dialog` 底色完全一致；
3. **规则穷举**（el.matches × 全样式表）：命中规则 = **裸选择器 `[data-theme="night"]`**；
4. **构建产物核对**：源码 `:global([data-theme='night']) .dialog` 被 Vue 编译器编译为 `[data-theme='night'] { background: #262a34 }`——**`.dialog` 限定符被丢弃**（:global 与后代选择器混用的编译坑）。

**结论**：夜间模式下 stage 根元素（data-theme 挂载点）整体被涂成不透明 #262a34，凡卡片未覆盖处（缝隙/空槽/窗口底部/缩进胶囊背后）即露黑块。与历轮全部现象吻合（纯色/夜模式才有/与面板展开无关/隐藏两侧后因待办卡贴近满窗而不可见）。

## 二、修复

- ConfirmDialog 夜间底色改走**令牌**（--dialog-bg/--dialog-fg，日/夜主题四处置定义），彻底移除 :global 裸选择器写法；
- E2E 回归断言：夜间 .stage 计算底色必须透明（黑块回归信号）；确认框夜 #262a34 / 日 #fff。

## 三、人工重验

夜间模式看缝隙、隐藏面板空位、缩进胶囊背后——黑块应全部消失。**若仍可见请截图**（届时按同样诊断流程定位下一层）。

## 三、发版过程中的环境事故与处置（教训归档）

**现象**：`npm run dist` 在 win-unpacked 改名/写产品 exe 环节 100% 失败（EPERM/EBUSY/UNKNOWN），换目录/重试 7+ 次无效，甚至残留目录无法删除；一次尝试卡死 70 分钟（CPU 仅 2s，内核级阻塞）。

**根因**：本机**同时启用三个实时杀软**（腾讯电脑管家 + 火绒 + Windows Defender），对 246MB 新 exe 抢扫，打包器随后的改名/删除操作全部撞锁；部分文件被 AV 过滤驱动**无限期持有**（阻塞而非报错）。

**处置（有效）**：
1. 换**全新输出目录**（避开被死锁的残留文件 —— rm 步骤不再触发）；
2. 给 electron-builder 打**机器本地重试补丁**（不入库）：`app-builder-lib/out/util/electronGet.js`（extractArchive 的 rm/rename 退避重试）与 `out/electron/electronWin.js`（asar integrity 读写重试）——本次打包改名被拦 4 次后自动通过。
   - ⚠️ `node_modules` 重装后补丁丢失；重打包若再遇此错，重建补丁或为三杀软加目录信任区（推荐后者，一劳永逸）。
