## 一、提示（toast）归属 —— 这是本轮的实病

### 审计结果（你说"把所有页面的提示都检查一遍"，我全查了）

| 项 | 现状 |
|---|---|
| toast 元素定义在哪 | **只有主窗**（`MainTodoWindow.xaml` 的 `ToastPill`） |
| 提示调用点 | 全仓 **40 处**（`ShowToast` 30 处 + 各二级窗直调 10 处） |
| 路由方式 | `ClusterController.ShowToast` 写死 `_main.ShowToast(...)` → **一律发到主窗** |
| 后果 | 设置窗/历史窗/编辑窗/详情窗/模板窗触发的提示，全部画在**主窗底部**；主窗被设置窗（模态、更大）盖住时，提示基本看不见 |

**为什么设置窗的提示会跑到主窗**：因为 toast 从一开始就只做在主窗上，控制器也只往主窗发——不是"设置窗没提示"，而是"设置窗的提示被发到主窗去了"。这条在验收清单 八.5（设置窗「−」到下限弹提示）里还挂着未验收，是我漏的口径，认账。

### 改法（你会看到什么）

- 规则：**提示出现在你正在操作的那个窗口里**（该窗口自己的底部居中），不再固定发主窗。
- 覆盖：主窗、模板窗、设置窗、历史窗、编辑窗、详情窗——任一窗口触发的提示都显示在自己身上。
- 判定方式：取当前**活动窗口**（`IsActive`）作为提示宿主；若活动窗口不是本应用的（比如你切到别的软件），回落到主窗。
- 视觉与时长**完全不变**：深色胶囊、底部居中、离底 28px、0.18s 淡入上移、2.2s 自动消失。
- 实现上抽一个公共 `ToastPresenter`（一处实现，6 个窗口共用），主窗原来的 XAML toast 一并迁过去，避免两套代码。

**算通过**：
1. 打开设置窗，点「−」到下限 → 提示出现在**设置窗底部**（不再被盖住、不再出现在主窗）；
2. 设置窗里改自启/导入/恢复尺寸 → 提示同样在设置窗上；
3. 历史窗里删除/导出 → 提示在历史窗上；
4. 主窗里完成待办、批量删除 → 提示仍在主窗上（不变）；
5. 模板窗里新建/删除模板 → 提示在模板窗上。
