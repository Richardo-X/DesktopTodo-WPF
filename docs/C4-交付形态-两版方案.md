# C4 交付形态 · 两版方案（对比用）

> 用途：用户要求先**记录**其提出的 C4 需求（方案A），再由 AI **不参照该需求**独立拟一份（方案B），供用户对比取舍。
> 两版均为方案、未实施；实施内容以用户对比后的裁定为准（可取A、可取B、可混）。
> 共同基线（需求文档已定稿，两版都必须满足）：**安装版为主 + Velopack 自动更新；便携版不做；卸载不删数据；应用本身不联网、免登录、数据本地。**

---

## 方案 A · 用户版（2026-11-08 记录）

### 需求要点（用户原话归纳）

1. **安装包 + 应用内更新**。
2. **标题栏提示**：有新版本时，在标题栏「桌面待办」右侧显示「有新版本！」。
3. **设置页新增「检查更新」按钮**：点击自动检查——
   - 无新版本：提示「当前为最新版本」；
   - 有新版本：显示**新版本号 + 新版本更新内容**，询问是否更新；
     选「是」→ 应用更新到最新版并重新打开应用；选「否」→ 回到设置页不更新。
4. **「新版本提示」开关**：开 = 有新版本时标题栏提示；关 = 不提示；**默认开**；只影响新版本通知。

### 体验说明书 v1（AI 依方案 A 拟，待批准）

- **安装与数据**：双击 Setup.exe 安装（开始菜单/桌面图标、控制面板可卸载、免管理员）；待办数据自动继承（数据在 `%APPDATA%`，与安装无关）。
- **标题栏提示**：开关开 + 有新版本 → 「桌面待办」右侧出现「有新版本！」；开关关 → 不出现；开关从关切到开 → 立刻检查一次。
- **设置页**：「检查更新」按钮（点击 → "检查中…" → 无新版提示「当前已是最新版本」/ 有新版弹窗：版本号+更新内容+是否更新——是=自动下载安装并自动重启；否=回设置页）；「有新版本提示」开关（默认开，只影响标题栏提示）。
- **背景检查时机**：应用启动时自动检查一次；之后不打扰。

## 方案 B · AI 独立版（2026-11-08 拟，拟定时未对照方案 A）

设计立场：单用户个人桌面应用；"发布"=在本机构建新版本；数据本地、应用离线。

1. **交付形态**
   - Velopack per-user 安装（装 `%LocalAppData%`，免管理员），**自包含**（不要求机器装 .NET 运行时），版本号 SemVer 从 1.0.0 起。
   - 发布脚本一键出包：`dotnet publish`(Release, self-contained, win-x64) → `vpk pack` → 产出 `Setup.exe` + releases 目录（全量/增量包 + 更新说明文件）。
   - 卸载走 Velopack 自带卸载器；`%APPDATA%` 数据保留（卸载不删数据 ✓）。

2. **更新来源与联网**
   - 更新源 = **本机 releases 目录**，实现为**可配置字符串**（默认本机；将来改网络地址只改配置不动代码）。
   - 零联网；换网络源后仅"检查/下载"两步联网。

3. **更新触发与提示（B 版核心）**
   - 启动后**延迟 10 秒静默检查**（不挡启动），此后不轮询；设置页手动检查随时可用。
   - 有新版本：**一次性 toast**「新版本 x.y.z 已就绪，可在设置中更新」+ **设置页顶部常驻徽标**「有新版本 x.y.z →」；无新版本时两者都不出现。
   - **不打断式确认**：不弹窗逼问；更新动作全部收敛在设置页——点徽标/按钮 → 显示「当前版本 → 新版本」与更新说明 → 「更新」按钮 → 下载进度 → 「重启完成更新」按钮，**用户自己掌控重启时机**（避免打断正在进行的编辑）。
   - 检查失败静默（源不存在/清单格式错不弹窗）；手动检查失败才明确报错。

4. **设置页**
   - 「当前版本 x.y.z」+「检查更新」按钮 + 「自动检查更新」开关（默认开；关 = 不自动检查，手动检查不受限）。
   - 更新说明 = 随包发布的 RELEASE-NOTES.txt，按版本展示。

5. **安全栏**
   - 更新只动安装目录，不碰 `%APPDATA%` 数据。
   - Velopack 旧版本目录保留（机制性可回滚；UI 不做回滚入口）。
   - 更新重启前若有未保存输入，走既有「未保存提醒」；更新重启与单实例互斥衔接（旧实例先退、新实例后起）。

6. **批次拆分**：B1 打包基建（出包+安装/卸载/数据继承验证）→ B2 更新主链路（检查/下载/重启）→ B3 设置页 UI（版本显示/按钮/开关/徽标/toast）。

## 定稿（2026-11-08 用户裁定，A/B 混合）

1. **交付**：Velopack 安装包（自包含、免管理员）+ 本机 releases 目录更新源（零联网）+ 一键发布脚本；版本号 1.0.0 起，设置页显示当前版本。
2. **检查**：开关开 → **每次启动**自动检查；开关关 → 启动不检查（**手动「检查更新」按钮不受限**）。检查失败：后台静默、手动明确报错（取方案 B）。
3. **标题栏提示**：有新版本且开关开 → 「桌面待办」右侧显示「有新版本！」——**普通文字样式（非按钮）**，字号 = 标题字号 × 2/3，颜色醒目（accent），可点击（悬停手型）；**点了才弹更新提示窗，不自动弹**。
4. **更新提示窗**（标题栏点击 / 设置页「检查更新」同一逻辑；弹窗锚定活动窗口上方，设置页触发时在设置页上方）：
   - 内容：新版本号 + 更新内容（随包 RELEASE-NOTES）；
   - 按钮：**「重启完成更新」**（下载+应用更新+自动重启）/ **「暂不更新」**（关窗）。
   - 无新版本：提示「当前为最新版本」。
5. **「新版本提示」开关**：默认开；关 = 启动不检查 + 立即清除已有标题栏提示；手动按钮不受限。
6. **降级/回滚**：每个版本有独立安装包可手动回滚；安装器内不做版本询问（Velopack 不支持），改**应用内版本标记**（见下分析）。
7. **未保存输入**：用户裁定不存在该场景，更新重启前不做额外提醒。

### 降级与数据兼容分析（2026-11-08 AI 思考，随定稿生效）

- 安装器内"版本对比询问"Velopack 原生不支持（需自制引导器，成本高不做）。
- 替代：**应用内版本标记**——存档记录上次运行版本，启动时当前 < 记录 → 提醒"数据可能不完全兼容，建议导出备份"。
- 旧版本读新数据：按字段名+缺省兜底，新增字段读不坏；但旧版本**写档会丢弃**它不认识的新字段
  （新功能相关数据回默认，非损坏）。缓解 = 降级提醒 + 备份 + 数据结构"只增不改不删"纪律。
- 其他：发布必递增版本号；应用内更新只升不降（降级靠独立安装包）；更新重启与单实例衔接；
  首启钩子无动作；杀软拦截直接报告；「当前为最新版本」用现有确认框/轻提示；
  弹窗跟随活动窗口（既有机制）；「有新版本！」普通文字+悬停手型+点击弹窗。
