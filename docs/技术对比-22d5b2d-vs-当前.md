# 技术对比：`22d5b2d`（快捷窗未实验版） vs 当前版（`ffdb5fa`）

> 目的：为"缩放逻辑 / 显示逻辑"的版本对比提供精确口径。只列**实际代码差异**，不掺推测。
> 对比基线：`22d5b2d`（2026-10-12，拖动/缩放实验开始前的最后一笔）↔ `ffdb5fa`（2026-10-13，角标修复）。

## 一、两版完全相同的部分（无代码差异，逐文件核对）

这些文件在两版之间 `git diff` 为空，即**几何与摆放的底层完全一致**：

| 文件 | 职责 |
|---|---|
| `src/TodoWpf.Core/Windows/ClusterLayout.cs` | 三窗几何：主 470×640、侧 310×640、缝隙 4px 固定；缩放上下限与钳制；三窗矩形推导 |
| `src/TodoWpf/Windows/WindowPlacement.cs` | 原子批量摆放：`BeginDeferWindowPos/DeferWindowPos/EndDeferWindowPos`、各边按物理像素取整、`SWP_NOZORDER|NOACTIVATE|NOCOPYBITS` |
| `src/TodoWpf/Windows/ToolWindowChrome.cs` | `WS_EX_TOOLWINDOW`（不进任务栏/Alt+Tab） |
| `ClusterController` 内：缩放输入、同帧 `UpdateLayout()` 同步 | 鼠标横向增量 → `_scale` → 帧内合并提交；`_resizing` 期间强推一次布局 |

**含义**："窗口摆在哪、多大、缝隙多少"两版一样；差异全部集中在**"每个窗的内容怎么跟着缩放显示"**。

## 二、逐窗差异

### 1. 待办主窗（470×640）

| 项 | `22d5b2d` | 当前 |
|---|---|---|
| 窗口矩形 | 目标矩形（含缩放，逐帧变） | 同左（**未改**） |
| 内容缩放 | `LayoutTransform`，比例 = 原始 `_scale` | `LayoutTransform`，比例 = **`NormalizedScale`**（按窗口取整后的实际宽度反推） |
| 缩放角标 | 位于**被缩放的 CardContent 内**（设计坐标右下角） | **移出缩放内容**，钉在窗口右下角；自身用渲染层 `ScaleTransform`（锚点右下角）随档位变化 |

- 角标差异的后果：旧版角标会跟着"内容晚一拍"一起滞后（相对边框跑位）；新版位置恒在角上、只变大小。
- `NormalizedScale` 的后果：消除"内容宽度与窗口宽度差零点几像素"导致的**右缘裁一条 / 缝隙变宽**（用户视频慢放实证过）。

### 2. 已完成窗（310×640）

| 项 | `22d5b2d` | 当前 |
|---|---|---|
| 窗口矩形 | 目标矩形（逐帧变，含"左缘随主窗右缘平移"） | 同左（**未改**） |
| 内容缩放 | `LayoutTransform`，比例 = 原始 `_scale` | `LayoutTransform`，比例 = **`NormalizedScale`** |

（仅注释与比例取整口径不同；结构、机制一致。）

### 3. 快捷添加窗（310×640）—— 差异最大

| 项 | `22d5b2d` | 当前 |
|---|---|---|
| 窗口矩形 | **目标矩形**（310×640×档位，逐帧变） | **固定"画布矩形"**：`max(设计尺寸, 设计尺寸×缩放上限)`，**永不随缩放变化**（仅位置随锚点走） |
| 卡面 | 铺满窗口（随窗口一起变大小） | 固定设计尺寸 310×640，**右上角对齐 + 渲染层 `ScaleTransform`（`RenderTransformOrigin=1,0`）** |
| 内容缩放 | `LayoutTransform`（比例 = 原始 `_scale`） | 由卡面渲染层缩放承担（比例 = `NormalizedScale`） |
| 移动路径（`MoveCluster`） | 用目标矩形 | 用**画布矩形**（与缩放路径一致） |
| 命中/点击 | 整窗即卡面，无余量 | 卡面外有**透明画布余量**（会吞掉该区域的点击；此前的"窗口区域收窄"因会裁剪绘制已被移除） |
| 内容显隐开关 | 无 | `SetContentVisible()`（恒为可见，仅测试备用） |

## 三、由此产生的行为差异（用户可感知）

| 场景 | `22d5b2d` | 当前 | 原因 |
|---|---|---|---|
| 缩放中：快捷窗右缘/缝隙 | 会看到右缘位移、"缝隙变宽" | 稳定不抖（用户已确认） | 旧版每帧改窗口矩形，合成器把"上一帧表面"按新矩形重贴；新版窗口矩形不变 |
| 缩放中：快捷窗尺寸跟手程度 | 与主窗同（都受布局节拍支配） | 与主窗同帧（渲染层变换不触发布局） | 旧版内容走 `LayoutTransform`（要重排才可见） |
| 按下/松开缩放柄 | 无特殊处理 | 无闪动（同因：矩形不变） | — |
| 移动整体 | 正常 | 正常（曾因移动路径用目标矩形而"移动中被裁、松手恢复"，已修为画布矩形） | 见上行 |
| 缩放角标 | 位置随内容滞后跑位 | 位置恒定、大小随档位 | 角标移出缩放内容 |
| 主窗/已完成窗 | 基准 | 与基准一致（仅比例口径取整更精确） | — |

## 四、结论（一句话）

> 两版的**几何与摆放底层完全相同**；差异只在"内容如何跟随缩放"：
> `22d5b2d` = 三窗统一走"改窗口矩形 + 内容 `LayoutTransform`"；
> 当前版 = 主窗/已完成窗同前者（仅缩放比例按物理像素取整更精确 + 角标移出缩放内容），
> **快捷窗改为"窗口矩形恒定的固定画布 + 卡面渲染层缩放"**，并因此多了"卡面外透明余量吞点击"这一代价。
