## 一、为什么日期控件一直没解决（先认账）

| 环节 | 事实 |
|---|---|
| 需求文档 §2.7 | 只写功能「日期选择（最早~今天）」，**没有视觉要求** |
| 验收清单 50 项 | **没有日期控件项**（八.8 仅"历史窗可正常打开与返回"） |

所以不是"设计上放弃"，是**起了样式名却没实做**，且从未进入验收口径。我的漏项。

## 二、开关（开机自启）—— 改完你会看到什么

**现状**（数字来自代码）：42×23 轨道，底色 = 6% 黑（几乎与面板同色），描边 26% 黑，滑块 17px **中灰**。
→ 观感：一个灰描边空胶囊里坐着一颗灰点，开/关两态差异很小。

**改法 A（推荐）**：滑块一律**白色**，开启时轨道填**实色强调蓝**。

| | 关 | 开 |
|---|---|---|
| 轨道 | 实色浅灰 `#D6DBE4`（夜间 `#3A3F48`） | 实色强调蓝 `Brush.Accent` |
| 滑块 | 白 + 1px 极淡描边（把白钮从浅灰轨道上分离出来） | 白 |
| 动画 | 0.16s 缓出（已有，不变） | 同 |

**改法 B（贴原型）**：只把滑块改白，其余沿用原型色系（关：6% 黑底+26% 黑边；开：淡蓝底+蓝色描边+白钮）。
代价：开启态"淡蓝底 + 白钮"对比仍偏弱，仍可能觉得不够明显。

> ⚠️ 冲突提示：A/B 都与原型 CSS 原文（`on` = 淡底 + **蓝色滑块**）不一致。原型那套在 36×20 的浏览器里成立，放到 42×23 的 WPF 里就发灰。这属于"改设计"，需你拍板。

**算通过**：开关在关/开两态一眼能分清；滑块是白的、边界清楚；点击有滑动动画；夜间主题下同样清楚。

## 三、日期控件（历史窗 3 处）—— 改完你会看到什么

### 3.1 字段本身（三处统一）
- 28 高、圆角 6、1px 描边（卡片描边色）、底色 = 输入区白（夜间深灰）
- 文字 11px、等宽数字，日期显示 `2026/11/05`
- 右侧一枚 13px **日历线稿图标**（新增图标，弱灰色）
- 鼠标悬停：描边加深；点进编辑：描边变强调蓝；禁用：整体半透明（与原型 `input:disabled{opacity:.5}` 一致）
- 不带系统 3D 边、不带系统日历按钮

### 3.2 点开后的日历弹层（关键：不重做这个等于没修）
- 白卡、圆角 8、1px 描边、柔和投影（弹层不在窗体内，不受上次"投影从圆角漏出"影响）
- 头部：`‹  2026年11月  ›`，标题 13 半粗，箭头 24×24 圆角 6、悬停出底色
- 星期行：`一 二 三 四 五 六 日`（**周一起始**；要周日起始告诉我，一行改动）
- 日期格：28×28、圆角 6；悬停出底色；选中 = 强调蓝底白字；今天 = 蓝色细描边
- 越界日期（早于最早归档 / 晚于今天）灰显不可点（与现有范围限制一致）
- 点日期即选中并关闭；点窗外、按 Esc 关闭
- 弹层约 232×248

### 3.3 三处位置
历史窗顶部「前一天 / 日期 / 后一天 / 回到今天」中间的 118 宽那枚；底部导出区「至」前后两枚 102 宽。

**算通过**：三个日期框外观一致、不再是系统方框；点开是同一套中文日历；选日期后列表跟着刷新；日期范围限制照旧。
